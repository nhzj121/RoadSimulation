## 任务书要求如何对应到我们的工作

| 原要求或关联要求 | 当前模块对应实现 | 交接时的边界 |
|---|---|---|
| 运输过程增加随机事件至少 2 种 | 交通拥堵、车辆故障；增加全局天气影响作为第三类环境扰动 | 晴、雨、雪、雾是同一类天气的不同状态，不重复计数 |
| 评分表提及随机事件 3 种以上、5 种以上 | 当前提供三类；AUTO 天气场景预生成随机天气表，单车事件有概率触发 | 不据此保证某一成绩等级，评分还涉及司机行为和全局优化性能 |
| 使仿真参数更贴近实际场景 | 天气与拥堵降低驾驶进度，故障暂停，维修后继续 | 当前系数、概率为演示假设；基础驾驶时长与循环步长仍有限制 |
| 构造测试数据，对结果进行预测、模拟和验证 | 分段计算预期工作量；实际数据库中检查多站货物、库存与事件归档 | 单元测试、数据库联调与地图视觉验收分别记录 |
| 优化目标实时统计 | 提供活跃事件、驾驶进度、受影响时间、损失工作量 | 尚未接入算法对比和成本指标；这些数据不等于最终任务延误 |

任务书中的“司机行为状态”是另一项要求；不把车辆故障状态重复计入司机行为成果。缺货、货损、天气、拥堵、故障是任务书举例，并非要求本周全部实现。与沙箱有关的场景保存和回放属于为后续实验提供支持的扩展。

## 本轮补充的功能

- 新增车辆影响详情：天气系数、拥堵系数、后端有效速度、维修/拥堵预计结束仿真时刻、当前驾驶进度。
- 说明剩余正常驾驶工作量的含义，不将它显示为预计到达时间；装卸阶段说明天气不延长装卸。
- 缓存缺失时，天气模式从数据库补回已在执行的任务及有序多站节点；未完成路线准备的 ASSIGNED 任务仍走原注册流程。
- 多站任务缺少缓存车辆起点时使用任务起点；车辆监控可显示后端活跃车辆，不依赖地图图标是否已经绘制。
- 故障已到预计结束时间、但状态机尚未恢复时，监控有效速度继续显示 0，消除状态与速度的矛盾。
